### 2.3 规则

- **通关**：结算同时满足速度与正确率 → 记为该小关达标；不达标可无限重试。
- **阶段解锁**：阶段内全部小关达标 → 解锁下一阶段。
- **最佳成绩**：每关记录历史最佳（速度优先，同速比正确率）。
- **自由模式**：不计入关卡进度与解锁，但计入单字统计（设置可开关）。
- **加练**：结算后可选错题加练，加练不计进度；升级为智能选字（见 4.3）。

### 2.4 文章素材来源（待确认）

- 原则：**仅使用公有领域文本**，页面标注出处与作者。

- 拉取方式：`scripts/fetch-articles.ts` 一次性抓取 → 清洗 → 存 `scripts/sources/articles/*.txt`，构建时生成 `articles.json`（含标题/作者/出处/难度/正文分段）。

## 三、界面设计

### 3.1 布局（桌面优先，最大宽度 960px 居中）

```
┌────────────────────────────────────────────────────────────┐
│ ① 顶栏   ← 返回地图   阶段名 · 关卡名          存档按钮 ⚙   │  56px
├────────────────────────────────────────────────────────────┤
│ ② 统计条  速度 42 字/分 │ 正确率 96% │ 完成 12/20 │ 用时 18s │  44px
├────────────────────────────────────────────────────────────┤
│ ③ 文本区（批次/段落）                                        │
│     未输入灰 · 当前字加粗高亮 · 正确柔绿 · 错误柔红            │
│     单字/字根每批 20，文章按段落，切换带 200ms 淡入           │
├────────────────────────────────────────────────────────────┤
│ ④ 编码提示条   好 → V B （女 V ＋ 子 B）  已输入位高亮        │  40px
├────────────────────────────────────────────────────────────┤
│ ⑤ 虚拟键盘  QWERTY 三行，下一步键高亮呼吸；反馈闪烁常驻尾态   │
└────────────────────────────────────────────────────────────┘
```

- 窄屏（<768px）：文本区字号下调，键盘按键等比缩放，统计条换行。
- 字根练习无 ④（只提示键位），文本区显示字根名（批次展示）。

### 3.2 配色（低饱和，统一收敛）

| 语义 | 变量 | 色值 | 说明 |
|---|---|---|---|
| 未输入文字 | `--text-pending` | `#98a2b3` | 灰 |
| 已完成正确 | `--text-done` | `#6aa87f` | 柔绿 |
| 已完成出错 | `--text-wrong` | `#c47b7b` | 柔红 |
| 当前字 | `--text-active` | `#1f2937` 加粗 + 背景 `#eef2f7` | 深灰加粗 |
| 键盘底色 | `--key-bg` | `#f3f4f6` | |
| 键盘下一步 | `--key-hint` | `#cfe0f3` | 柔蓝呼吸 |
| 正确反馈 | `--key-ok` | `#b7dcc4` | 绿闪后常亮 |
| 错误反馈 | `--key-bad` | `#e8bcbc` | 红闪后常亮 |
| 超时提示 | `--key-timeout` | `#ecd9a6` | 黄闪（不常亮） |

- 红绿灰明度对齐（L\* 接近），避免刺眼；深色模式预留变量，不在 V2 实现。

### 3.3 交互细节

1. **批次**：单字/字根每批 20（可配置 `batchSize`），当前批完成后 200ms 淡入下一批；文章整段显示，段落完成自动滚动/换段。
2. **虚拟键盘**：
   - 高亮“下一步应按键”（`code[input.length]`）；输入越界时高亮空格键（简码上屏）。
   - 正确：该键绿闪 180ms → 保留绿色常亮直至下一次反馈；错误：红闪 180ms → 保留红色常亮；超时：黄闪 180ms（不常亮）。
   - 键帽显示五区底色条（横竖撇捺折各一色，低饱和）。
3. **超时**：自“本字首键或上一字完成”起计时，超过关卡 `timeoutMs` 未有任何输入 → 键盘对应键黄闪一次，并计入 `timeouts`；连续超时每周期再闪。
4. **字符状态**：`pending` 灰 / `active` 加粗深灰 / `done-clean` 绿 / `done-wrong` 红。字完成时有错 → 红，否则绿。
5. **无障碍**：所有状态色同时有非颜色冗余（当前字加粗+下划线，错误字下方波浪线）。

## 四、数据与存档

### 4.1 存档结构 v2

```ts
interface SaveV2 {
  version: 2
  exportedAt: number
  progress: {
    unlockedStages: string[]              // 已解锁阶段
    levels: Record<string, LevelResult>   // 每关最佳与完成状态
  }
  mistakes: MistakeBook                   // 沿用
  stats: Record<string, CharStat>         // 新增：单字统计
}

interface CharStat {
  attempts: number     // 完成次数
  errors: number       // 累计错误击键
  totalMs: number      // 累计输入耗时（字完成时累加）
  lastAt: number
}

interface LevelResult {
  passed: boolean
  bestSpeed: number
  bestAccuracy: number
  attempts: number
  timeouts: number
  at: number
}
```

- localStorage：`wubi.v2.save` 单键存储，统一读写。
- **迁移**：检测到 `wubi.v1.progress` / `wubi.v1.mistakes` 时自动合并迁移，迁移后保留旧键（不删除）。
- 存档写入采用 300ms 防抖。

### 4.2 导出 / 导入

- 导出：下载 `wubi-save-YYYYMMDD.json`（含 version、exportedAt、全部数据）。
- 导入：文件选择或粘贴文本；校验 `version` 与结构；确认后覆盖并刷新页面。
- 冲突策略：整档覆盖（导入前提示“将覆盖当前进度”）。

### 4.3 单字统计与智能加练

- 每字完成时：`attempts+1`、`totalMs += 本字耗时`；出错时 `errors+1`。
- 派生指标：`errorRate = errors / max(attempts,1)`、`avgMs = totalMs / max(attempts,1)`。
- **智能加练池**：对存在错误或耗时显著偏高的字打分
  `score = 0.6 × 归一化错误率 + 0.4 × 归一化平均耗时`，按 score 降序取前 N（默认 10），加练次数按 score 分档 2–4 次。
- **掌握**：连续 2 次无错完成 且 `avgMs` 优于该关卡中位数 → `mastered = true`，不再默认进入加练池。
- 结算弹窗新增“本次最难字”展示（耗时前 3）。

## 五、测试系统（可编程驱动）

目标：Agent 用脚本高速验证全流程，不依赖真实键盘。

1. **引擎级**（已有）：`judge.test.ts` / `stats.test.ts` 纯函数用例。
2. **视图驱动 harness**：`src/testing/harness.ts`
   - `mountPractice(levelId)`：挂载练习视图并等待数据就绪。
   - `typeText(harness, text)`：按目标文本自动生成正确键序列并注入（模拟 keydown）。
   - `typeErrors(harness, plan)`：按计划注入错误键序列。
   - `getState(harness)`：读取速度/正确率/进度/当前字/键盘高亮键。
   - `advanceTime(harness, ms)`：配合 vitest fake timers 推进时间，触发超时与统计刷新。
3. **关卡冒烟批量**：`src/testing/levels.smoke.ts`（vitest）遍历全部关卡：自动正确通关 → 断言结算达标；并生成“错误路径”用例。
4. **浏览器内接口**（可选，仅 DEV）：`window.__wubiTest__ = { press, state, jump }`，供 Playwright/控制台脚本使用。
5. 命令：`pnpm test`（全部）、`pnpm test:watch`、新增 `pnpm test:levels`（仅关卡冒烟）。

> 该方案零新增依赖（全部基于 vitest + @vue/test-utils）。
