# 关卡难度调整指南

> 本文档说明调整关卡难度（速度阈值、正确率、题量、超时、出题内容、阶段结构）需要编辑哪些文件、如何修改与验证。
> 当前为 V3 体系：6 阶段 / 43 关，其中 S4–S6 为跟打器关卡（`type: 'typing'`）。

## 一、难度由哪些参数决定

每个小关对应一个 `LevelConfig`（定义见 `src/types.ts`）：

| 字段 | 含义 | 影响 |
|---|---|---|
| `require.speed` | 达标速度阈值 | 通关速度门槛（zigen 为 **键/分**，danzi/article 为 **字/分**） |
| `require.accuracy` | 达标正确率阈值（0–1） | 通关准确率门槛 |
| `length` | 题量（zigen / danzi）；article 为参考字数 | 单局长度 |
| `timeoutMs` | 每键 / 每字超时（毫秒） | 仅提醒并计入超时次数，**不影响**速度与正确率 |
| `pool` | zigen 键位池 | 字根关覆盖范围 |
| `source` / `starts` | danzi 出题池与首码过滤 | 单字关内容 |
| `articleIds` | article 引用篇目 | 文章关内容 |
| `intro` | intro 教学关正文段落 | 教学关内容 |
| `pattern` / `drillRepeat` / `drillShuffle` | drill 出题：每字连打 N 遍；`drillShuffle` 每局随机字序（默认按 `starts` 即口诀序） | 口诀 / 全码肌肉记忆训练 |
| `requireFull` | 强制全码：禁用简码 + 空格上屏 | 全码训练关 |
| `mix` | 多源按权重混合（如 short1 : short2 = 1 : 3） | 备用字段（当前无关卡使用） |
| `shape` / `rootCount` | 识别码字型过滤（1 左右 / 2 上下 / 3 杂合）与真实字根数过滤 | 识别码分型、三/四字根关 |
| `script` | 口诀训练脚本：`[...]` 为提示行（不训练）；其余行汉字按顺序全部输入（标点/空格仅显示） | 口诀关（s2-short1-a/b），进入时自动居中 |
| `showShort1` | 拆字面板额外显示当前字的一级简码（如 `一级简码：G + 空格`） | 一级简码训练关（short1-a/b/mix；全码关不显示） |
| `showShorts` | 拆字面板显示简码规则说明（一/二/三级打法）与当前字全部层级简码 | 二级简码训练关（short2 五区关） |
| `typing.mode` | 跟打器模式：climb / sprint / speedup / marathon / endless / gauntlet | 决定判定流程与结算方式 |
| `typing.source` | 跟打器内容源：common3500 / words2 / words3 / words4 / words-mix / article | 决定素材来源 |
| `typing.range` | 数组源切片 `[start, end)`（缺省为全量；words3/words4 通常省略） | 关卡内容范围 |
| `typing.groupSize` / `typing.groupSpeed` | climb：每组字数（词组关为词数）与默认通关速度档（字/分） | 组用时上限 = 组内汉字数 × 60 ÷ 所选档位；练习页可在 35/50/70 档间切换（默认取 `groupSpeed`，当前为 50） |
| `typing.durationSec` / `typing.charTarget` | sprint 限时秒数 / sprint 与 endless 的达标字数 | 挑战目标 |
| `typing.speedup` | speedup 逐段速度门槛数组（段数超出时末档复用） | 各段速度要求 |
| `typing.errorLimit` | endless 错误上限（达到即结束） | 无尽模式结束条件 |
| `typing.poolSize` | sprint / endless 预生成文本长度 | 单局可用文本量 |
| `typing.segments` | gauntlet 段落定义：`{ source, articleIds?, range?, count?, speed }[]` | 综合测试分段与各段门槛 |

> 教学关（`type: 'intro'`）的 `require` 仅为占位，达标以「点击已阅读」为准。
> 脚本关的 `length` 必须等于脚本中训练汉字总数（`levels.smoke.test.ts` 有一致性校验）。

> 编码关达标判定：`速度 ≥ require.speed 且 正确率 ≥ require.accuracy`（见 `src/views/PlayView.vue`）。
> 跟打器关（`type: 'typing'`）：climb 按每组实际汉字数与**所选速度档**判定（档位 35/50/70，默认 `groupSpeed`）；sprint / endless 按 `charTarget`；speedup / gauntlet 按各段 `speed`；marathon 直接使用 `require`（速度与正确率）。`require` 在 speedup / gauntlet 中同时作为通关段位基准速度，climb / sprint / endless 仅作地图展示参考。
> 阶段解锁：阶段内**全部**小关达标 → 解锁下一阶段（见 `src/composables/useLevels.ts`）。

## 二、主要编辑文件

### 1. `src/data/stages.ts`（改难度只需改这里）

工厂函数负责生成关卡配置，签名如下：

```ts
function zigen(id, title, keys, length, timeoutMs, speed, accuracy = 0.9)
function zigenRadicals(id, title, length, timeoutMs, speed, accuracy = 0.9)
function danzi(id, title, source, starts, length, timeoutMs, speed, accuracy = 0.85, opt = {})
function intro(id, title, paragraphs)
function typing(id, title, cfg: TypingConfig, requireSpeed, requireAccuracy)
```

- `danzi` 的第 9 个参数 `opt` 透传 `LevelConfig` 的可选字段（`pattern` / `drillRepeat` / `drillShuffle` / `requireFull` / `mix` / `shape` / `rootCount` / `script` / `showShort1` / `showShorts`）。
- `intro` 教学关仅需标题与段落数组，无题量与超时。
- `typing` 的 `cfg` 为 `TypingConfig`（见 `src/types.ts`），`requireSpeed` / `requireAccuracy` 为地图展示与段位基准。

- **改速度 / 正确率 / 题量 / 超时**：直接改对应调用里的数字。
- 数字顺序（以 `zigen` 为例）：`(id, 标题, 键位池, 题量, 超时ms, 速度, 正确率)`。

示例：

```ts
// 原：zigen('s1-zigen-heng', '横区字根 G F D S A', HENG, 200, 4000, 30)
// 改：题量 200→150、超时 4000→3500、速度 30→35、正确率默认 0.9→0.92
zigen('s1-zigen-heng', '横区字根 G F D S A', HENG, 150, 3500, 35, 0.92),
```

**V3 跟打器关（S3–S6）调整要点**

- **S3 识别码关**（达标统一为 25 字/分 · 85%）：`source: 'idcode'` 时用 `shape`（`[1]` 左右 / `[2]` 上下 / `[3]` 杂合）与 `rootCount` 过滤题池，`length` 为单局题量；三/四字根全码关用 `source: 'freq1'` + `rootCount: 3/4`。识别码各关题量按 86/98 池较大值设定（250/210/170/200）。
- **S4/S5 爬坡**：改 `typing.range` 调整字/词范围，改 `typing.groupSize` 调整每组题量；`typing.groupSpeed` 为默认通关速度档（需为 35/50/70 之一，练习页可实时切换）；`length` 由 `typingLength()` 自动按切片跨度或数据量推导（words3/words4 无 `range` 时为 200）。
- **S4/S5 综合关**（`s4-common-mix*` / `s5-words-mix`）：marathon + 数组源 + `typing.sample`（每次进入随机抽题量）；常用字综合关通过 `typing.range` 指定上 / 中 / 下频段（当前三段为 `[0,1167)` / `[1167,2334)` / `[2334,3500)`），词组综合关覆盖全量词池；达标速度与正确率在 `typing()` 的 `requireSpeed` / `requireAccuracy` 参数中；改 `sample` 调整单局题量。
- **S6 挑战**：按模式改 `typing.durationSec`（冲刺时长）、`typing.charTarget`（冲刺/无尽目标字数）、`typing.speedup`（逐段门槛，段数超出时末档复用）、`typing.errorLimit`（无尽容错）、`typing.segments[].speed`（毕业综合各段）；耐力/终极关的速度与正确率在 `typing()` 的 `requireSpeed` / `requireAccuracy` 参数中。
- **修改后**：typing 配置会由 `levels.smoke.test.ts` 的「跟打器关卡配置一致性」自动校验（必填字段、range 边界、article 引用、S6 模式字段）。

- **增删 / 重排小关**：在对应阶段的 `levels` 数组里增删条目、调整顺序。
- **增删 / 重排阶段**：编辑 `STAGES` 数组；解锁顺序按数组相邻关系自动推导。
- 常用键位常量：`HENG / SHU / PIE / NA / ZHE / ALL_KEYS`（文件顶部）。
- 文件顶部注释中的「N 阶段 / M 小关」与训练量说明应同步更新。

### 2. 出题内容相关（仅当要改题目来源时）

| 目的 | 文件 | 备注 |
|---|---|---|
| 字根键名 / 口诀 / 注释 | `scripts/sources/zigen.json` | 25 键元数据 |
| 键盘字形 / 练习字形 | `scripts/sources/zigen-glyphs.json` | 由 `scripts/build-glyph-table.py` 生成 |
| 排除字根（易混淆 / 不常用 / 空字形） | `scripts/sources/zigen-exclude.json` | 黑名单，两个构建脚本均读取 |
| 单字出题池逻辑（简码 / 常用字 / 识别码、首码过滤） | `src/data/pool.ts` | 改逻辑在此 |
| 码表 / 常用字分级 / common3500 | `scripts/sources/*` + `scripts/build-chars.ts` | 生成 `chars*.json` 与 `common3500.json`（字频降序） |
| 跟打器词组表 / 黑名单 | `scripts/build-words.ts` | 从 86 码表按权重提取二/三/四字词，黑名单在脚本内 |
| 文章内容（题目 / 作者 / 出处 / 难度 / 段落） | `scripts/sources/articles.json` | 正文汉字数即实际字数；S6 与自由模式使用 |

> 改动 `scripts/sources/*` 后**必须**运行 `pnpm data:build` 重新生成 `src/data/generated/*`（该目录不入库，CI 部署时也会自动生成）。

### 3. 类型定义（仅当要新增难度字段）

若要新增与难度相关的字段（如每题限时、随机范围等），需：
1. 在 `src/types.ts` 的 `LevelConfig` 增加字段；
2. 在 `src/data/stages.ts` 的工厂函数中补上默认值；
3. 在使用处（`PlayView.vue` / `LevelSelectView.vue` / 引擎）读取该字段。

## 三、调整与验证流程

```bash
# 1) 编辑 src/data/stages.ts（必要时编辑 sources）
# 2) 若改了 sources，重新生成数据
pnpm data:build

# 3) 本地走查（地图达标要求、练习结算门槛）
pnpm dev

# 4) 关卡冒烟（S1–S3 按正确编码自动通关；typing 配置校验 + 9 关爬坡第 1 组达标）
pnpm test:levels

# 5) 提交前门禁（必须全绿）
pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm data:verify
```

CI 部署（`.github/workflows/deploy.yml`）会先执行 `pnpm data:build` 再 `pnpm build`，因此 sources 改动无需提交 generated 产物。

## 四、注意事项

- **存档兼容**：修改阈值**不会**改变已保存的 `passed` 状态与最佳成绩，新的达标判定即时生效。若想让玩家按新难度重新通关，需在「存档」页重置或清除 `localStorage` 的 `wubi.v2.save`。重命名 / 删除关卡 id 会让旧成绩成为孤儿数据（项目早期不处理迁移）。
- **爬坡进度兼容**：修改 `typing.groupSize` 会改变组划分，旧 `groupIndex` / `groupBests` 语义失效；调整后建议在「存档」页重置或清档。修改 `range` 同理。
- **测试**：
  - `src/testing/levels.smoke.test.ts` 自动遍历 `STAGES`（跳过 `type: 'intro'` 的教学关），并校验所有 typing 关的配置一致性；9 个 climb 关会挂载 `TypingView` 驱动第 1 组达标。增删关卡无需改测试结构，但关卡总数 / id 唯一性断言需同步。
  - `src/views/PlayView.test.ts` 引用了具体关卡 id（如 `s1-zigen-heng`、`s2-short1-a`、`s2-intro`），**重命名或删除**关卡 id 时需同步。
  - `src/views/TypingView.climb.test.ts` 固定引用 `s4-common-1`；`TypingView.modes.test.ts` 固定引用 S6 各关 id 与 `free`，重命名时需同步。
- **文档同步**：关卡数量 / 阶段表出现在 `README.md`、`doc/需求文档.md`（第十章）、`doc/V3跟打器重构设计.md`，增删关卡或阶段时一并更新；`doc/V2重构设计.md` 仅 S1/S2 仍有效。
- **文章素材**：`length` 对 S6 文章源仅作参考，实际字数由文章正文决定；`scripts/verify-articles.ts` 要求每篇 ≥200 汉字且 `stages.ts` 引用的篇目存在。
- **速度单位**：zigen 关为「键/分」，danzi / article 为「字/分」；typing 关统一为「字/分」（climb 词组关也按实际汉字数计，不按词数）。地图与结算的显示单位由 `level.type` 判定。
- **跟打器达标口径**：climb 每组必须全部正确完成（错误只消耗时间、不阻止继续），且用时 ≤「组内汉字数 × 60 ÷ 所选速度档」；达标自动进入下一组、未达标自动重来（不弹结算卡片）；sprint / endless 按完成字数 `charTarget`；speedup / gauntlet 按各段 `speed`（speedup 段数超出 `speedup` 数组时复用末档）；marathon 按 `require` 的速度与正确率。段位由 `src/engine/rank.ts` 按速度或字数档计算。
