# 提交规范

本项目的提交信息遵循 [Conventional Commits](https://www.conventionalcommits.org/)，与需求文档 3.4-7 一致。

## 格式

```
<type>(<scope>): <subject>
```

- **type**（必填）：提交类型，见下表。
- **scope**（选填）：任务卡编号（小写），如 `t0.1`、`t1.3`；无明确任务时省略。
- **subject**（必填）：简体中文，动词开头，不超过 50 字，句末不加句号。

## 类型

| type | 含义 |
|---|---|
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `chore` | 构建、工具链、配置、依赖 |
| `data` | 数据源与生成数据 |
| `test` | 测试用例 |
| `docs` | 文档 |
| `refactor` | 重构（不改变外部行为） |
| `style` | 格式调整（不影响逻辑） |

## 提交粒度

- 每完成一个任务卡（`T*.*`）且通过 DoD 后提交一次，提交信息带对应 `scope`。
- 大体积数据源与生成数据使用 `data` 类型单独提交。
- 不将 `node_modules`、`dist`、`src/data/generated` 纳入版本控制（见 `.gitignore`）。

## 完成定义（DoD）

提交前必须依次通过：

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

全部零错误方可提交。数据相关任务额外执行 `pnpm data:verify`。

## 示例

```
chore(t0.1): 初始化 Vite+Vue3+TS 工程基座
feat(t0.2): 添加 hash 路由与视图骨架
data(t1.1): 引入 wubi86 码表与拆字数据源
feat(t2.1): 实现五笔判定引擎与单测
fix(t3.3): 修正简码空格上屏边界
```
